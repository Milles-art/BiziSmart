# S4f — Read-only stock movement history

Expose real append-only ledger entries from S4d. This adds no adjustment, sale, supplier accounting or offline write.

- GET /products/{product}/movements requires receive_stock and an approved-device session. Product is a tenant-scoped public ID; inactive products remain readable, archived products return 404 as on existing nested stock routes. Never revive catalogue archive workflows in this slice.
- Optional batch_id must be a bat_ public ID belonging to this product and tenant. Foreign/unknown/product-mismatched batches return the same 404; malformed IDs return 422. page>=1 and per_page=1..100/default50. Filter before pagination; order created_at descending then id descending, including stable ties.
- Return {movements:[{id,product_id,batch_id,batch_number,type,qty_change,qty_after,created_at,user_id,device_id,receipt}]} and page/per_page/total meta in the standard no-store envelope. All IDs are prefixed public IDs. qty_change and qty_after are signed exact base-quantity strings, timestamps UTC ISO. receipt is the existing immutable quantity/package/version snapshot, without cost, phone, PIN, token or staff/device names. Product/batch/user/device relationships retain tenant scopes. No internal IDs or raw atoms leave the server.
- qty_after is the batch's recorded balance immediately after that movement, not current batch stock or an overall product balance. Reads never change batches, movements or receipt snapshots. Idempotent receipt replay still produces only one entry.
- Products → Stock provides Batches and Movement history tabs; each batch can open its filtered history, and All movements clears that filter. History rows show server change/after quantities, batch label, movement type, Tanzania display time and original packaging receipt metadata. Empty/error/loading states, retry and Previous/Next history preserve filters. Real receipt writes invalidate movement queries. No browser persistence or client quantity calculation.

Acceptance: owner/stockkeeper access; manager/cashier denial; tenant/product/batch ID isolation; strict pagination and stable ordering; counted/gram exact formatting and historical receipt version; duplicate replay/read-only counts; hidden costs/PII/internal fields; UI filter/pagination/error retry and server receipt invalidation; desktop/phone receiving-to-history flows and preserved design.
