# S4g — Online stock corrections

D068: every stockkeeper correction requires owner approval; all online correction results must be non-negative. Offline sales retain accept-and-flag. Owners can correct stock under their existing adjust_stock permission. This slice changes batch quantity only, not cost, expiry, recall or quarantine flags. Inactive products can be corrected for physical stock accuracy; archived products remain unavailable on public stock routes.

POST /stock/adjust/preview accepts operation_id (UUID), batch_id (public), qty_change (nonzero signed exact base quantity string), reason (required trimmed text, max500). Requires adjust_stock and approved-device session. Returns snapshot {operation_id,batch_id,product_id,qty_change,qty_before,reason}, payload_hash, qty_after and approval_required. No writes. Reason is encrypted in the ledger and omitted from audit properties.

POST /stock/adjust accepts those fields plus expected_qty (exact signed reviewed balance) and optional approval_token. Laravel derives the same snapshot; it never accepts a supplied digest. Stockkeeper approval uses auth/supervisor-check permission adjust_stock and the preview hash: eligible owner PIN plus fresh TOTP only. Manager/stockkeeper cannot approve. Owner direct correction needs no separate grant. Grants bind requester/session/device/operation/snapshot for five minutes; consumption and batch/ledger/audit writes commit atomically.

Changed balance returns 409 STOCK_CHANGED and requires fresh preview/approval. Negative result returns400 INSUFFICIENT_STOCK. Checked batch and held/eligible aggregate int64 arithmetic; overflow422. UI: batch Correct stock opens preserved MUI dialog; enter signed base quantity/reason, Review correction displays server before/change/after. Approval fields for stockkeepers only; clear PIN/TOTP and RTK mutation result after each approval attempt, grant only transient. Confirm submits frozen reviewed operation. Uncertain network/server result allows retry of identical operation, without editing or abandoning until resolved; definite validation/conflict errors allow fresh review.
