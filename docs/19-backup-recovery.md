## Format and tooling

`infrastructure/prod/backup-crypto.php` uses standard OpenSSL CMS: AES-256-CBC EnvelopedData with RSA-OAEP/SHA256, then SHA256 SignedData over the ciphertext. Recovery verifies the signature with the separately trusted signing certificate before decryption. The signing certificate is explicitly pinned (`-nointern`); `-noverify` skips CA-chain validation, not signature/content verification. The host's OpenSSL1.1.1k rejected CMS/GCM in a non-sensitive compatibility probe, so GCM is not used or claimed. See the [official OpenSSL CMS command documentation](https://docs.openssl.org/1.1.1/man1/cms/).

Seven checks pass on both host OpenSSL1.1.1k and local OpenSSL3.5.7: binary/Unicode roundtrip; wrong recovery key; wrong signing certificate; altered ciphertext; truncation; existing-output refusal; failed-output cleanup. No failed authentication publishes plaintext. CLI fixture: `infrastructure/prod/test-backup-crypto.php`, private temporary test root required.

`infrastructure/cpanel/encrypted-backup.php` is specific to the existing account. It refuses another database/linked key directory, holds a private exclusive lock, uses a private native-client option file, invokes single-transaction dumping, stages only owner-readable SQL/env, packs code/build and a SHA256/count manifest, seals the result, uploads only encrypted bytes to R2 and hashes the read-back. The private recovery key never goes to the server. Staging files are removed on normal completion/failure; a later locked run cleans only its own exact known stale filenames. Hard-killed staging is still private and must be monitored.

`infrastructure/local/verify-hosted-backup.php` refuses endpoints other than127.0.0.1:3307, authenticated input outside the protected copies directory and unknown filename formats. It extracts only three required archive entries, checks manifest hashes, creates a random new local database, invokes the production restore helper with exact confirmation, compares every table/count, checks foreign keys and proves an existing encrypted owner value can be decrypted using the backed-up APP_KEY. It never boots the recovered environment or contacts production/providers. Plaintext and only its own DB are removed in finally; passing recovery must include those cleanup checks.

`infrastructure/cpanel/check-runtime.php` is a private CLI monitor for public readiness, scheduler freshness/clean status, daily encrypted/offsite backup freshness and stale plaintext staging.
